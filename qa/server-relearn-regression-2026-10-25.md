## Office 嵌入图片范围核验（同日）

为避免仅凭 PPTX 个例推断，在服务器当前 `document-api` 容器的 `/tmp` 中生成同一张仅含唯一文字 `OFFICEPIC74219` 的图片，分别嵌入纯测试 DOCX、PPTX、XLSX，再直接调用现有 `parse_document`（不上传、不写数据库）。同一张 PNG 单独调用解析器可识别该文字。

| 输入 | 解析结果含图片文字 | 观察 |
| --- | --- | --- |
| 独立 PNG | 是 | OCR 正常读出唯一标记。 |
| DOCX 内嵌图片 | 否 | 输出普通段落和 `<!-- image -->` 占位。 |
| PPTX 内嵌图片 | 否 | 仅输出 `<!-- image -->`，无可检索分段。 |
| XLSX 内嵌图片 | 否 | 仅输出工作表单元格内容。 |

代码路径与实测一致：DOCX/PPTX 使用默认 Docling 转换，未再对嵌入图片 OCR；XLSX 使用 `openpyxl` 的 `iter_rows(values_only=True)`，完全不读取图像；独立图片走 `parse_image_with_ocr`，PDF 有单独 OCR/补全流程；旧式 `.doc/.ppt/.xls` 先转成现代 Office 格式后进入相应路径。准确结论是：**Office 文件中只存在于嵌入图片里的文字，在当前学习流程中没有可靠提取**。并不表示每张图片都重要，也不表示有相同原生文字时该信息一定缺失。
